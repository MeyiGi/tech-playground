
Нужен именно `opencv-contrib-python-headless`: он содержит `cv2.ximgproc.thinning`. Обычный `opencv-python` этого модуля не содержит. В одном окружении следует оставить один вариант пакета OpenCV. Программа сохраняет изображения без графического окна.

Пути по умолчанию привязаны к расположению `main.py`. Для другого файла:

```bash

```

Объект должен быть белым, фон чёрным; `--invert` предназначен для тёмных объектов. Входное изображение бинаризуется по правилу `pixel > threshold`. Полутоновая морфология отдельно демонстрируется на воспроизводимом синтетическом изображении с неровным фоном и мелкими деталями.

## Как работают операции

Пусть `A` — изображение, `B` — структурный элемент. В плоском элементе ненулевые позиции выбирают соседей; сами значения маски не прибавляются к яркости.

| Операция | Правило | Назначение |
|---|---|---|
| Эрозия `E(A)` | Минимум по соседям | Уменьшает белые объекты |
| Дилатация `D(A)` | Максимум по соседям | Расширяет белые объекты |
| Opening `O(A)` | `D(E(A))` | Удаляет мелкие светлые объекты |
| Closing `C(A)` | `E(D(A))` | Закрывает мелкие тёмные отверстия и разрывы |
| Внутренний контур | `A − E(A)` | Граница внутри объекта |
| Градиент | `D(A) − E(A)` | Полоса вдоль границы с обеих сторон |
| White top-hat | `A − O(A)` | Мелкие светлые детали |
| Black top-hat | `C(A) − A` | Мелкие тёмные детали |

Для бинарного изображения минимум эквивалентен условию «все выбранные соседи белые», максимум — «хотя бы один белый». Для полутонового используются реальные значения яркости 0–255. Перед вычитанием тип расширяется, затем результат ограничивается 0–255, как в OpenCV: переполнения `uint8` нет.

### Структурный элемент и границы

`structuring_element` создаёт квадрат, крест, горизонтальную/вертикальную линию, диагональ и диск. Демонстрация использует размеры 3, 5, 7 и 11. Диск определяется евклидовым радиусом; это не обещание совпадения с дискретизацией `cv2.MORPH_ELLIPSE`. Библиотеке передаётся та же самая маска.

В собственных функциях `anchor=(строка, столбец)`, в OpenCV порядок обратный: `(x, y)`. По умолчанию берётся центральная позиция. Для плоской морфологии используется соглашение OpenCV: для обоих фильтров сосед выбирается по смещению `позиция_в_ядре − anchor`. Для симметричного центрального ядра это обычные определения морфологии; у несимметричных ядер отражение при дилатации в разных библиотеках может отличаться.

Поддержаны `constant` (константа), `edge` (повторение края) и `reflect` (отражение без повторения крайнего пикселя, OpenCV `BORDER_REFLECT_101`). Нейтральная константа по умолчанию: **255 для эрозии, 0 для дилатации**. Для нулевого фона явно задаётся `border_value=0`. Это существенно: при нулевом фоне эрозия уменьшает даже белый объект, занимающий весь кадр.

### Zhang–Suen

Нумерация соседей со слайдов 21–23:

```text
P9 P2 P3
P8 P1 P4
P7 P6 P5
```

`N` — число белых соседей. `S` — число переходов 0→1 по циклу `P2,P3,…,P9,P2`. Для удаления белого `P1` необходимы `2 ≤ N ≤ 6` и `S = 1`.

В первом подшаге дополнительно нужны `P2·P4·P6 = 0` и `P4·P6·P8 = 0`. Во втором — `P2·P4·P8 = 0` и `P2·P6·P8 = 0`. На каждом подшаге сначала вычисляются условия для всех пикселей, затем отмеченные пиксели удаляются одновременно. Второй подшаг работает с результатом первого. Полные итерации повторяются, пока оба подшага не перестанут менять изображение.

Слайд 21 подробно показывает только первый набор условий; в реализации есть оба. Проверка числа переходов защищает соединения между ветвями, ограничение по соседям — в том числе концевые пиксели. Это дискретный thinning, а не поиск точной евклидовой медиальной оси; строгая однопиксельность каждого возможного локального рисунка не гарантируется.

### Guo–Hall

Для булевых соседей вычисляются:

```text
C  = (!P2 & (P3|P4)) + (!P4 & (P5|P6))
   + (!P6 & (P7|P8)) + (!P8 & (P9|P2))
N1 = (P9|P2) + (P3|P4) + (P5|P6) + (P7|P8)
N2 = (P2|P3) + (P4|P5) + (P6|P7) + (P8|P9)
N  = min(N1, N2)
m0 = (P6|P7|!P9) & P8
m1 = (P2|P3|!P5) & P4
```

Пиксель удаляется, если `C = 1`, `2 ≤ N ≤ 3` и `m` текущего подшага равен нулю. Здесь тоже два подшага, одновременное удаление и остановка по отсутствию изменений. Вход принимается как 0/1, bool или 0/255; выход всегда 0/255.

Чтобы честно сравнить границы, перед `cv2.ximgproc.thinning` добавляется рамка из нулей, после обработки она удаляется. Без этого OpenCV оставляет крайние пиксели без обработки, а наша функция учитывает для них нулевой внешний фон.

### Скелет по эрозиям

Дополнительно реализовано объединение `E_k(A) − Opening(E_k(A))` по всем последовательным эрозиям до пустого изображения. Используется крест 3×3 и нулевой фон. Простое повторение эрозии до конца даст пустое изображение, поэтому остатки нужно накапливать. Полученный скелет не обязан совпадать с Zhang–Suen или Guo–Hall и может содержать разрывы; для сохранения связной тонкой структуры предназначены алгоритмы thinning. В OpenCV такой отдельной функции нет: сравнение выполнено с независимой композицией `erode`, `dilate`, `subtract`, `bitwise_or`.

### Неплоский структурный элемент

На слайде 33 приведены высоты `[[0,1,0],[1,2,1],[0,1,0]]`. Здесь ноль — допустимая высота, а не выключенная позиция. Неактивные позиции задаются отдельной маской `footprint`.

Эрозия: `min(f(x+b) − s(b))`. Дилатация: `max(f(x−b) + s(b))`. При дилатации отражаются высоты, маска и anchor — соглашение SciPy. Результат возвращается в `float64` без обрезания: например, 255 + 10 даёт 265. По умолчанию граница повторяется (`edge` / SciPy `nearest`). Тесты также проверяют асимметричные высоты, чётный размер, смещённый anchor, константу и отражение.

## Сравнение и вывод

Критерий сравнения — число несовпадающих пикселей, максимальная и средняя абсолютные ошибки по всему изображению, включая края. Нулевые ошибки показывают совпадение с соответствующим эталоном на проверенных данных. Тесты дополнительно проверяют небольшой пример с известным ответом, удаление шума, закрытие отверстия, неизменность входа, сходимость thinning, сохранение связности и отверстия у кольца, сохранение концов тонкой линии и некорректные входы.

Собственные функции позволяют проследить формулы, библиотечные дают независимый практический эталон. В отчёте записано время одного запуска; по нему нельзя делать вывод о стабильном ускорении без прогрева и повторных измерений. Различия между скелетами разных алгоритмов сами по себе не являются ошибкой.
